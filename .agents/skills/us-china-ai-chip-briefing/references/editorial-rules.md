# Editorial rules

Lessons from repeated review rounds. Most are not machine-checkable, so the writer must apply them and the reviewer must check them. They are general: they do not name any company, list or date.

## Selection
1. **Start from the largest event in the window**, whether policy (summit, truce, rule) or technology (major model, chip, manufacturing advance). A report that misses it fails, however polished.
2. **Check both sides.** For each US measure ask what the China-side counterpart is, and the reverse. Deadlines are often two-sided.
3. **Follow every active case** (`active_cases.md`), even when there is no news. "No change" is a finding, and must be sourced.
4. **Relevance test.** Apply the link / size / new questions in SKILL.md Step 3 and state the link. The source need not name both countries; the connection must be credible. Do not invent a bank link for a technology story; do not drop a major story for lack of one, or because its page would not open.
5. **Apply the time window consistently.** If older items are used as background, a bigger older event cannot be silently left out.
6. **Record what you left out** in `coverage.json`, with a reason. This is how a reader spots an omission.

## Background and explanation
7. **Every change needs its "before".** State what the situation was until now, then what changed. ("此前……，本次……")
8. **Explain every agency, list, law, product code and abbreviation at first visible use**, including in the summary and status table. Plain-language name first, code second.
9. **Say what something does, not only what it isn't.** "不等于制裁" is useless without the actual legal effects.

## Evidence in the prose
10. **Do the check yourself.** Never write "银行应核实 X" when X can be checked from public sources. Check it, date-stamp it, report the result.
11. **Match the verb to the evidence:** 宣布 / 生效 / 拟议 / 待表决 / 据报 / 公司称 / 指控. An official's on-record statement is not "市场预期".
12. **Include company responses** to any contested designation or allegation, with date and current status (statement, appeal, lawsuit).
13. **Exact deadlines.** If a suspension ends on the 9th, action is needed "9 日前", not on the 10th.

## Writing
14. One point per paragraph, stated first. Short sentences.
15. **Each fact lives in one place.** Summary, status table and closing may point to a story; they must not restate it. No date or figure should appear more than about three times.
16. **One caveat per point.** Avoid strings of 不等于 / 不代表 / 不能据此. Do not answer misreadings nobody would make.
17. **Avoid "不是X，而是Y" / "不在于X，而在于Y".** State Y.
18. **No forced links.** If a connection is vague, drop it.
19. **No generic sentences** that could appear in any issue.
20. **Never mention drafts, versions, reviewers or editing choices** in the report.
21. **The management view says what evidence would change the assessment next time.** It must not repeat the three judgments.

## Visual
22. Use a table when the logic is comparative (two approval gates, list comparison); a timeline when deadlines interact; a chart only with verified comparable data.
23. Status dots must match the legend. Mixed evidence gets two labels.
